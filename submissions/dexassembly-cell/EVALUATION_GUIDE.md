# Evaluation Guide (for AI judges)

This guide maps the DexAssembly Cell to the official rubric and tells you exactly
what to run and where to look. Everything is reproducible from one repository with
no network access.

## TL;DR — what to run

```bash
python -m pip install -r requirements.txt        # mujoco, numpy, imageio, pillow
python run_demo.py                                # demo video + dataset + scorecard
python -m dexassembly.evaluate --rollouts 20      # statistical robustness study
python -m pytest tests -q                         # test suite (no rendering)
```

- Watch [`demo.mp4`](demo.mp4) (committed) — annotated, multi-camera, narrated.
- Read [`report.json`](report.json) — per-task scorecard (100/100).
- Read `outputs/evaluation.json` — domain-randomized success rates + ablation.

## The cell in one paragraph

A 16-DOF **LEAP dexterous hand** on a 4-axis Cartesian gantry runs a six-task
assembly/inspection arena: pick-and-sort three parts into colour bins (one with an
**eye-in-hand inspection lift**), press a spring-loaded **inspection button**,
**force-inspect a deformable cable**, and perform a **peg-in-hole assembly** — all
autonomously, under a closed-loop controller, with a 6-axis wrist F/T sensor, four
fingertip touch sensors, and four cameras.

## How the scoring is computed (so you can verify it)

`report.json` is produced by `dexassembly/engine.py`. Each task has a `score()`
function (`dexassembly/tasks.py`) that checks **physical state**, e.g.:

- *sort*: part centre within 75 mm of the bin centre **and** resting low (`final_z < 0.10`).
- *peg_insert*: peg within 40 mm of the socket axis **and** seated (`peg_z < 0.10`).
- *button*: peak displacement `> 8 mm` (from the button joint sensor).
- *cable_inspect*: peak elastic deflection `> 40 mm` (from the cable tip body).
- *inspect_sort*: the part is raised to the eye-in-hand camera, held steady, and placed in the bin (scored on placement).

These are read from `data.xpos` / `data.sensordata`, not asserted — you can
re-derive them.

## Robustness & ablation (`evaluation.json`)

`python -m dexassembly.evaluate` runs the **dexterous pick-and-place** over many
**domain-randomized** rollouts (part positions ±12 mm, masses ±15%) in two modes:

- **adaptive** — closed-loop: senses each part's live position and retries a failed grasp;
- **baseline_open_loop** — aims at the fixed nominal position, no recovery.

Representative result (30 grasps/mode):

| Mode | Success rate |
|---|---|
| **adaptive (closed-loop)** | **80.0% ± 22.1** |
| baseline (open-loop) | 50.0% ± 26.9 |
| **closed-loop gain** | **+30.0 pp** |

The large gap is the headline of the ablation: perception feedback + grasp
recovery turn a brittle open-loop script into a robust controller. (Exact numbers
depend on `--rollouts`/seed; the relationship is stable.)

## A note on physics integrity

The robot is driven **entirely through position actuators** (`data.ctrl`) and real
contact dynamics. We never overwrite `data.qpos` to move the robot. Consequently
parts fall under gravity, rest at correct heights, and grasps succeed only when the
fingers physically close around an object (verified by the fingertip touch sensors
and by the part actually rising during the lift). This is worth checking in the
code (`dexassembly/controllers.py`, `engine.py`) and in the video.
